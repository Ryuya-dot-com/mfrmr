# ConQuest candidate-002 execution incident for mfrmr 0.2.3

Status: first arm failed semantically after process exit status zero; remaining
five arms not launched, 2026-08-12. Candidate 002 is consumed and cannot be
reused. No external comparison was performed.

The authorized Binary command began with a multiline `/* ... */` explanatory
preamble. ConQuest 5.47.5 reported `Unknown command or argument: /*Generated`,
then an invalid regression, missing data file, missing model/estimation, and
history/show errors. It nevertheless emitted `End of Program` and the host
process returned status zero. Therefore neither exit status zero nor the end
marker is a sufficient semantic-success rule.

Exactly one of the 50 expected paths exists: the Binary q31 combined console
log. All 49 native data outputs remain absent. RSM q31/q61, PCM q31/q61, and
Binary q61 were not launched.

## Repair

`build_conquest_overlap_command_template()` now emits executable commands
only, beginning with `datafile`. Explanatory prose remains in the bundle README
and summary, outside the `.cqc` input. The public summary reports
`comment-free executable input`, and regression tests reject `/*`, `*/`, and
`Generated by` in generated ConQuest commands.

This is a command-generation and semantic-exit validation defect, not a
likelihood or parameter-estimation discrepancy. Corrected commands require a
new source-bound candidate 003, new command/bundle/handoff hashes, and fresh
empty output paths. Candidate 002 results cannot be edited in place or pooled.
