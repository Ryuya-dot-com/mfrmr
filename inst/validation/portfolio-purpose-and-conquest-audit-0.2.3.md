# 0.2.3 portfolio-purpose and ConQuest audit

Status: repository-only strategic audit, 2026-08-11. This audit authorizes no
response generation, fit, external-program execution, confirmation, release
candidate, or public support expansion. It supersedes the *priority* of the
next action after the G-theory b1g24 issuance record; it does not alter or
invalidate that record's historical result.

## Executive decision

The 0.2.3 programme has accumulated valuable mathematical, numerical, and
execution-safety evidence, but its most recent G-theory sequence has reached
the point of diminishing scientific return. The correct portfolio action is:

1. freeze the b1g24 authorization machinery as complete infrastructure;
2. do not execute R0201 merely because it is technically issuable;
3. return to the 0.2.3 release spine and complete a claim-to-evidence
   disposition before any new high-replication run;
4. make exact matched ConQuest/TAM/FACETS overlap and deterministic reduction
   cases precede simulation wherever they can answer the same question; and
5. require every simulation to name the public or internal decision it can
   change and the precision needed to change it.

This is a stop against local optimization, not a conclusion that the existing
work was wasted. The execution-safety work found real failures. Its purpose is
now fulfilled. In hindsight, the late authorization slices could have been
consolidated into a smaller preflight; their separate completion is not a
reason to continue along the same axis.

## Numeric-resolution and rounding contract

External-software comparisons must preserve numeric resolution as part of the
estimand. The following rules apply to ConQuest and, with engine-specific
metadata, to TAM, immer, FACETS, and other comparators.

1. Never use screen, PDF, or copied table values for numerical acceptance when
   a native machine-readable export or stored object is available. In
   ConQuest, `set decimals` controls screen printing and is documented as
   ignored for file outputs; this does not by itself prove unlimited precision
   in every file type.
2. Retain the raw lexical token from every external numeric field before
   conversion to a binary floating-point number. Record file type, number of
   displayed decimals or significant digits, scientific notation, and any
   engine-specific missing/infinity token.
3. Cross-check the final native parameter export against the final iteration
   in the ConQuest `matrixout` history. A mismatch is a failed handoff, not a
   cross-engine discrepancy.
4. Record integration method, nodes and bounds, likelihood constants, weights,
   constraints, free dimension, convergence thresholds, termination reason,
   damping/update caps, and retained-iteration warnings before comparing
   estimates.
5. If and only if rounding to nearest with unit `u` has been established, a
   reported value `y` represents the interval `[y-u/2, y+u/2]`. Against an
   effectively unrounded value `x`, the compatible absolute-difference range
   is

   `max(0, abs(x-y)-u/2)` through `abs(x-y)+u/2`.

   If both values are rounded, use half the sum of their units. If the export's
   formatting rule is not established, do not invent this interval; label the
   result `reported-resolution-limited` and withhold sub-resolution claims.
6. Exact lexical equality, numerical compatibility at reported resolution,
   tolerance passage, and scientific equivalence are four different states.
   No one state silently implies the next.

The existing ConQuest normalizer parses native CSV numbers correctly for its
narrow scope, and the repository pilots already audit history-versus-export
differences. They do not yet retain raw lexical precision or classify a
rounding floor. That is a bounded improvement to make when the external core
is next run; it is not a reason to refactor all export code now.

## Is the large G-theory simulation necessary?

The planned 3,000 independent datasets, 108,000 fits, and 576,000 dependent
decisions had one defensible narrow purpose: calibrating a truth-blind
numerical boundary/stationarity rule with at most 100 independent trials per
primary cell. The earlier value audit correctly showed that 0 events in 100
gives a one-sided 95% upper bound near 0.0295 and about 95.2% probability of
seeing at least one event when the true rate is 3%.

That does not make the run necessary for the present portfolio. It cannot by
itself establish broad bias, RMSE, rank recovery, facet-effect recovery,
coverage, D-study stability, or sample-size guidance. Those targets have
different sampling variances and need claim-specific precision designs.

| Intended conclusion | Best first evidence | Large simulation now? |
| --- | --- | --- |
| Formula and parameterization are mathematically correct | Independent algebra, exact reduction, gradients, invariance, and boundary counterexamples | No. |
| mfrmr and ConQuest/TAM implement a matched overlap | Deterministic microcases with matched likelihood, constraints, integration, and native precision | No. |
| A numerical rule has an acceptably low false-ready rate | Sequential calibration with complete denominators and a prespecified bound | Possibly, but only if that rule remains a retained claim dependency. |
| Bias, RMSE, ranking, facet-effect recovery, or convergence envelope | ADEMP design with empirical-variance-based replication planning | Yes eventually for retained claims; not the current 100-per-cell rule by default. |
| Standard-error or interval coverage | Full-refit interval procedure and coverage-specific replication planning | Yes later; current point-fit calibration cannot answer it. |
| Broad G-theory or multivariate support in 0.2.3 | Not a 0.2.3 public claim under the version-placement contract | No. |

R0201 should therefore remain unexecuted until a claim-disposition review names
the exact unresolved numerical decision it can change. If no retained 0.2.3
claim depends on that decision, the simulation is deferred without treating
the prior infrastructure cost as a reason to continue.

## Reprioritized roadmap

### P0: stop and preserve

- Freeze b1g24 and all earlier G-theory execution machinery.
- Create no additional authorization layer and execute no reserved shard.
- Preserve hashes and records as reproducibility infrastructure and negative-
  control evidence.

### P1: restore the 0.2.3 release spine

- The overdue claim-disposition profile promised by the 2026-08-05 roadmap
  reassessment is now complete. It maps all 106 checklist items to 53
  `release_spine`, 32 `claim_conditional`, and 21 `deferred` rows, with a
  fail-closed fallback for every conditional claim.
- The deterministic public-surface audit is also complete. All nine fallback
  classes now fail closed; JML exploratory-SE wording, residual-PCA decision
  metadata, and GPCM owner/interpretation propagation were tightened without
  promoting a claim or running a simulation.
- The mandatory 53-row spine is now ordered into deterministic, numerical,
  external, empirical, and candidate/release waves. Its first structural row,
  the v3 readiness schema, is closed by its dependency-free fixture and
  privacy/terminology checks; runtime propagation remains separately open.
- Prioritize currently advertised RSM/PCM/bounded-GPCM JML/MML behavior,
  readiness propagation, candidate identity, package checks, and public-scope
  consistency over new model families.
- Treat G-theory in 0.2.3 as contract/parser/algebra prototype evidence only,
  consistent with its existing version-placement table.

### P2: close the highest-value external overlap

- Complete independent, candidate-bound binary and polytomous item-only
  ConQuest replications using the numeric-resolution contract above.
- Add a repository-only matched additive MFRM RSM/PCM microcase with Person,
  Rater, and Criterion facets, followed by one connected sparse and unequal-
  workload fixture. Do not claim general ConQuest parity from those cases.
- Keep TAM/immer/FACETS estimator modes separate. Do not pool raw JML,
  extreme-score adjustments, bias corrections, MML, CML, or CCML.
- Attempt a ConQuest GPCM comparison only after a probability-level
  `scoresfree`-to-bounded-GPCM mapping is exact. Otherwise record it as an
  informative non-overlap.

### P3: use simulations only at identified evidence holes

- Start with a deterministic or small sequential pilot.
- Predeclare the decision, estimand, failure denominator, precision target,
  and stop/escalation rule.
- Increase replication only when the confidence/MCSE calculation shows that
  more data can change the decision.
- Keep numerical-rule calibration separate from recovery, coverage, and
  operational sample-size studies.

### P4: resume G-theory on its version horizon

- For 0.2.4, validate a bounded univariate crossed/nested observed-score
  engine, including sparse/unbalanced design identification and full-refit
  uncertainty.
- For 0.2.5, add multivariate covariance estimation only after typed Stratum,
  shared-facet allocation, PSD/rank, and one-stratum reduction contracts pass.
- Do not let an early multivariate algebra prototype pull estimator and
  simulation work into 0.2.3.

## Admission rule for future expensive work

An expensive run may enter the active roadmap only when all five answers are
written before execution:

1. Which retained claim or release decision can change?
2. Why can algebra, a reduction case, or external microcase not answer it?
3. What is the independent sampling unit and target precision?
4. What result will stop, expand, defer, or narrow the claim?
5. What cheaper sequential design was considered?

Failure to answer any item is a portfolio-level NO-GO. This is intentionally a
scientific-value rule, not another implementation authorization subsystem.
