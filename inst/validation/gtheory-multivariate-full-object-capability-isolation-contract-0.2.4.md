# Draft.85c4k multivariate G-theory full-object capability-isolation contract

Date: 2026-08-24  
Scope: c4j four-route worker capability isolation and trusted receipt promotion  
Public status: unsupported

## Purpose and boundary

Draft.85c4k reruns the exact c4j qualification worker under a runtime-bound
macOS default-deny profile. It accepts the retained c4i repair receipt and c4j
complete-object qualification receipt, reconstructs a least-authority runtime,
executes the four lme4/glmmTMB ML/REML routes, and requires five negative
capability controls to fail in the intended way.

Successful c4k evidence may promote the c4j numerical candidate to a trusted
backend-qualification receipt. It does not authorize a planned response,
open a protected seed or truth vault, execute recovery, compute a coefficient,
invoke ConQuest, authorize inference or decisions, or change a public surface.

## Bound runtime

The runtime identity binds:

- the direct R executable and Rscript byte hashes;
- `/usr/bin/sandbox-exec`, `/usr/bin/env`, and the imported Apple system
  profile identities;
- the exact c4j and c4k worker source hashes;
- the 38 post-fit loaded namespaces and 27 native binaries captured by c4j;
- exact package paths, versions, DESCRIPTION hashes, native paths, and native
  hashes;
- the c4i Homebrew Fortran link and resolved-runtime identities; and
- the deterministic `C.UTF-8` locale required to reproduce factor-level and
  specification identities exactly.

The sandbox library is not an original library root. c4k creates one staged
runtime directory containing exactly 38 package-name symlinks, one for each
loaded namespace in c4j. Every symlink must resolve to the bound c4j package
path and reproduce its DESCRIPTION hash. The profile grants subpath read only
to those exact package/native roots. The 32 ancestor directories needed by
`realpath(3)` are separately bound as literal traversal reads; literal access
does not grant access to their descendants.

## Separated staging topology

The deterministic staging root has disjoint children:

```text
root/
  allowed/
    input/
    worker/
    source/
    runtime-library/
    output/
    scratch/
  denied/
    vault/
    forbidden-output/
```

Only `allowed/` receives staged subpath read. Only `output/` and `scratch/`
receive write access. The profile text contains no denied-root, vault,
forbidden-output, repository-validation-directory, or network allow rule.
The staging root itself and every non-staging path ancestor needed for
canonical path traversal receive literal read only.

## Capability request

The c4j request is projected to a capability request by changing only
`RepairRoot` and `OverlayLibrary` to the staged allowed root and staged runtime
library. The projected request receives its own hash. All other request fields,
including c4i/c4f identities, worker and source identities, seed, and four
tolerances, must equal the c4j candidate request exactly.

The normal sandbox receipt may differ from the c4j worker receipt only in the
request hash, process identity, process-identity hash, and receipt hash. The
controller reruns the complete c4j worker-receipt validator using the staged
overlay identity and requires all remaining receipt fields—including the four
complete fit objects and two complete parity objects—to be exactly equal.

## Process and environment contract

Each control launches `/usr/bin/sandbox-exec`, then `/usr/bin/env -i`, then the
direct R binary. The environment contains only the bound R home, staged
`R_LIBS_USER`, staged `TMPDIR`, minimal PATH, `C.UTF-8`, and UTC timezone.
The c4k wrapper runs the c4j worker as a child only in normal mode. The child
must exit zero, emit no process output, and return a typed receipt whose PID
differs from both the controller and c4j candidate PID.

The wrapper never promotes itself. Its result keeps all trust and downstream
flags false. Only the controller can promote the six independently validated
objects after the normal and negative controls pass.

## Negative controls

The six modes are fixed:

```text
normal
probe_vault_read
probe_source_read
probe_outside_write
probe_parent_environment
probe_unlisted_exec
```

Normal qualification must succeed. Synthetic denied-vault read, repository
source read outside the staged bundle, write below `denied/`, and `/bin/cat`
execution must be rejected by the sandbox. A synthetic parent-only environment
secret must be absent under `env -i`. The vault contains no planned seed,
response, reference output, or truth.

## Promotion semantics

All four trusted route rows bind the original c4j revalidated route receipt,
the sandbox full-fit-object hash, and the capability-profile semantic hash.
Both trusted pair rows bind the original c4j pair receipt and sandbox full-
parity-object hash. Promotion requires all six exact b1 object validations,
all six controls, the 22-row static policy audit, and every payload hash.

The resulting readiness boundary is:

```text
ProcessCapabilityIsolationReady = TRUE
TrustedReceiptProduced          = TRUE
QualificationEvidenceReady      = TRUE
BackendQualificationReady       = TRUE
OperationallyAdmissible         = TRUE

PlannedExecutionAuthorized      = FALSE
RecoveryEvidenceReady           = FALSE
EstimationReady                 = FALSE
InferenceReady                  = FALSE
DecisionReady                   = FALSE
PublicSupportReady              = FALSE
```

`OperationallyAdmissible=TRUE` applies only to the backend-qualification
evidence object. It is not study-lane authority.

## Fail-closed behavior

Changed parent receipts, workers, sources, package/native identities, locale,
symlink targets, request fields, profile rules, controls, full objects,
readiness flags, or payload hashes are rejected. Caller authorization cannot
reach the planned-response, recovery, or public-promotion callbacks.

The evidence is platform-specific and ephemeral. Rehashing a self-report or
editing a readiness flag cannot reproduce the controller's trust transition.
