# FACETS Feature Coverage Matrix

`facets_feature_coverage()` summarizes how `mfrmr` maps the main FACETS
output-table, output-file, and graph-menu surface to package functions.
It is a surface-coverage guide, not a statement that estimands,
conditioning, extreme-score handling, degrees of freedom, or numerical
results are equivalent.

Use this helper before migration work when you need a public,
user-facing answer to three questions:

- which FACETS outputs have a close `mfrmr` route,

- which outputs are only partially covered by structured R objects,

- which FACETS-specific outputs are not implemented or intentionally
  outside the current package scope.

## Usage

``` r
facets_feature_coverage(
  status = c("all", "implemented", "supported_with_caveat", "partial", "not_implemented",
    "not_targeted")
)
```

## Arguments

- status:

  Which rows to return. `"all"` returns the full matrix. Other values
  filter by the `Status` column.

## Value

A data.frame with columns:

- `FACETSArea`

- `FACETSFeature`

- `FACETSReference`

- `mfrmrRoute`

- `Status`

- `SurfaceCoverage`

- `StatisticalContract`

- `ValidationEvidence`

- `OperationalStatus`

- `Capability`

- `Limitation`

- `Alternative`

## Details

The matrix is based on the FACETS 64-bit output index, which lists
output Tables 1–14, DIF/bias plots, R/Web plots, output files, and
graph-menu curves. `mfrmr` intentionally prioritizes structured R tables
and reusable plot data over exact FACETS line-printer output.

The executed comparison uses FACETS 64-bit 4.5.0. The online update
history lists 4.5.3 (October 2026); current web help is not a
version-pinned executable specification. In particular, Table 13 web df
and executed df differ. The 4.5.1 history replaces the gtheory interface
while its help still names gtheory; mfrmr's independent G-study does not
depend on that menu. Numerical comparisons require their recorded
executable version, design and estimand.

Status meanings:

- `implemented`: a package-native route covers the substantive output
  surface; this status alone does not claim an externally matched
  statistical contract.

- `supported_with_caveat`: a package-native route exists, but the output
  must be read with explicit identification, validation, or scope
  caveats.

- `partial`: the concept is covered, but not the full FACETS formatting,
  option surface, file type, or external integration.

- `not_implemented`: a FACETS feature has no direct package-native route
  in the documented package scope.

- `not_targeted`: the feature is tied to FACETS UI, Web/Excel handoff,
  or another external program format and is outside the package scope.

The four contract axes are deliberately independent:

- `SurfaceCoverage` records whether a corresponding package surface
  exists; familiar visual grammar belongs only to this axis.

- `StatisticalContract` records the package-native statistical scope and
  never implies a FACETS-matched estimand.

- `ValidationEvidence` records whether this table establishes matched
  external numerical evidence. It currently does not; that conclusion
  requires a separate comparison using a matched model and estimand.

- `OperationalStatus` records route availability. A package route being
  available does not make `mfrmr` operationally interchangeable with
  FACETS.

For observed-score assessment planning,
[`mfrm_g_study()`](https://ryuya-dot-com.github.io/mfrmr/reference/mfrm_g_study.md)
and
[`mfrm_d_study()`](https://ryuya-dot-com.github.io/mfrmr/reference/mfrm_d_study.md)
support their documented univariate or multivariate component designs.
The older
[`mfrm_generalizability()`](https://ryuya-dot-com.github.io/mfrmr/reference/mfrm_generalizability.md)
/
[`mfrm_d_study()`](https://ryuya-dot-com.github.io/mfrmr/reference/mfrm_d_study.md)
pair has a different main-effects decomposition. Neither route
reproduces the FACETS interface to the external `gtheory` package. For
balanced ANOVA,
[`confint.mfrm_multivariate_gstudy()`](https://ryuya-dot-com.github.io/mfrmr/reference/confint.mfrm_multivariate_gstudy.md)
adds component SEs/intervals for a score or fixed composite under normal
random effects; two-score covariance intervals have explicit generalized
and conservative choices with signed bounds. Explicit `reml_profile`
variance and covariance intervals also accept MINQUE(0), with a separate
REML center and no sampling SE; two-score covariance profiles fit a
joint normal model and retain signed bounds.
[`vcov.mfrm_multivariate_gstudy()`](https://ryuya-dot-com.github.io/mfrmr/reference/vcov.mfrm_multivariate_gstudy.md)
separately supplies component sampling covariance/SEs for balanced ANOVA
and identifiable MINQUE sources using normal product moments; these
describe the original estimator, not REML. Individual G/Phi intervals
from balanced two-crossed-facet sources default to approximate MLS null
inversion. Undefined MLS widths are conservatively retained and flagged;
numerical availability does not guarantee coverage. G/Phi and SEM have
an explicit experimental `reml_profile` option for balanced or
identifiable incomplete sources; the separate REML fit retains original
ANOVA/MINQUE points and does not guarantee finite-sample or boundary
coverage. With `reference`, it maps one shared profile interval for
one-facet plans or nested plans with a common future child count,
including incomplete sources. Balanced crossed G also accepts explicit
experimental `score` intervals, retaining empty-set and numerical
diagnostics; Phi is not supplied by this route.
[`mfrm_multivariate_d_compare()`](https://ryuya-dot-com.github.io/mfrmr/reference/mfrm_multivariate_d_compare.md)
supplies a separate, limited normal-theory paired-plan calculation. See
[`vignette("mfrmr-gtheory", package = "mfrmr")`](https://ryuya-dot-com.github.io/mfrmr/articles/mfrmr-gtheory.md)
for a runnable workflow.
